# PPT 文案

## 版面限制

- 改写后的字数不要比原文多太多。同一行的几张卡片，说明文字的长度要相近，否则有的折成两行，标题就对不齐。
- 最后一两个字单独掉到下一行时，缩短句子，不缩小字号。
- 只换文字时版式不动。加删卡片、调整栏数这类改动工作量大，攒到一轮里一起做。
- 写回 PPT 后逐页导出图片，检查有没有溢出和错位。导出方法见 pptx skill。

## 各部分的写法

| 部分 | 写法 | 例 |
|---|---|---|
| 封面主标题 | 产品名或方案名，见 [selling-points.md](selling-points.md) 的"定位" | XX行业智能体 |
| 副标题 | 品类 · 场合 | 垂直AI解决方案 · 业务介绍与合作交流 |
| 封面卖点 | 一组三项，见 [selling-points.md](selling-points.md) 的"卖点组" | 数据私有可控｜兼容存量系统｜价值可量化 |
| 章节标题 | 名词短语，全篇用同一套序号 | 二、业务模式（一）聚焦AI分析与决策环节 |
| 卡片标签 | 四到八个字的名词短语 | 设备预警与诊断 |
| 卡片说明 | 一句动宾结构，一行放得下 | 提前识别设备异常，由大模型解析成因并给出处置建议 |
| 数据标注 | 固定格式"测评：指标" | 测评：光伏预测R²达0.95 |
| 步骤 | "名词短语：说明" | 数据接入：经授权只读接入，完成数据梳理 |
| 结论条 | 一句话，观点＋支撑，不复述本页内容 | 见 [selling-points.md](selling-points.md) 的"结论句" |

## 讲稿（备注）

讲稿是要念出来的。

- 用完整的句子和自然的连接词，例如"首先""然后""其中"。版面上的四字短语，在讲稿里展开成句子。
- 人称用"我们""各位"，不用"我方""合作方"。
- 语气正式，但不像念公文。例如："今天向各位介绍……""也希望听取各位的场景需求和建议。"
- 讲稿和版面说的是同一件事，数字一致。"【重点讲】"这类标记保留。

## 页面分工

- 每页回答一个问题。两页反复出现同一句话时，给两页定好分工，删去重复的那一处。例如一页讲"做什么、为什么"，另一页讲"怎么做"。
- 同一组模块在不同页的数量不一致（一页 7 个，另一页 4 个）时，指出来并统一。
- 全文的数字要前后一致。例如前面写"3项通过测评"，后面只列了两项。发现不一致时问用户，不自己改：对方可能另有考虑。

## 多轮修改现有 PPT

多轮修改时，不要每一轮都直接改 PPT 文件。

1. 用 pptx skill 把每页的文字提取成一份 Markdown 工作稿：每页一节，附当前截图，按版块列出文字（数字卡、流程、左右栏、结论条），最后是讲稿。另存一份原稿文字，方便对照。
2. 在工作稿开头放统一用语表，在工作稿里讨论和修改。
3. 一轮定稿后，一次写回 PPT，重新导出截图，放回工作稿核对。
4. 每个新版本都从原始 PPT 加上全部改动生成，不在上一版上叠加修改，这样版式不会越改越乱。
5. 文件名用版本号，例如 `<名称>_v1.pptx`、`<名称>_v2.pptx`，不用日期时间。原稿是 v1。
